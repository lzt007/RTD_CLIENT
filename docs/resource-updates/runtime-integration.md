# 正式资源事务接入进展

客户端正式启动、关卡 InitMap 和独立单包加载均在原协程之前校验；不增加测试开关。关卡收集音频、队伍角色分组、敌人包及角色敌人书本／分组，再由服务端补齐递归依赖。版本校验总期限 2 秒，下载同时最多两个，无进展期限 15 秒。

独立 ResourceCore 使用原 APK 的 Mono 类型与 LitJson，私有文件目录保存不可变内容、版本清单和 journal；ResourceGameBridge 管理游戏持有的包、音频缓存与协程门闩。构建生成实际端点和可选原缓存索引，二者不能进入 Git。内置缓存只在构建验证其内容身份与生产基线一致时复用，否则正式下载。

设备探针已证明旧引擎不能同时打开同 CAB 的两个包；Unload(false) 后旧对象仍可保留，新包可打开，旧包亦可重新打开。事务因此先完整下载并核对 SHA256，再卸载旧包的归档句柄、准备新包，整体成功才接受新清单；失败重新打开旧包并恢复游戏缓存。不得调用全局 Unload(true) 清理旧资源。

旧引擎裁剪后的 AudioSource 无 clip getter 和播放位置接口。补丁跟踪 SoundManager 原有 set_clip 调用，更新音频数组及已绑定声道；正在播放的已变更音频会重新开始播放。需在设备验收中核对听感，不能宣称已做到音频采样位置连续。

纯逻辑目前 40 项检查通过；结构测试检查三个远程下载入口、三个门闩、重复应用及未知结构拒绝。日文默认构建、签名和原有补丁检查已通过；设备在线启动批量核对 76 包约 317 ms、零下载并完成版本清单提交。完整设备验收仍在进行，不能将此文档视为整项功能完成证明。

首个生产版本快照已在备份后发布，共 375 个有效资源；所有原始资源文件保留。服务端本机指定监听地址测量 30 次单资源 resolve，p95 约 82 ms、最大约 188 ms，包含开发编译与回归争用；尚未达到设计的 20 ms 目标，需在无争用时区分服务处理时间与调度开销。

发布清单可选 requiredPrefabs 用于声明必须可导出的 GameObject 名称；客户端打开全部依赖归档后、接受新版本前验证这些导出。校验对象保留至事务结果明确，用于验证同 CAB 更新确实载入新对象并支持失败恢复；日志记录对象名称与实例 ID。客户端自己的当前关卡预制体需求仍会额外验证，不能依赖服务端声明替代。
