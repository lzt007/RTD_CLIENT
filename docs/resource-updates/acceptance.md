## 当前问题与修复验证

真机诊断发现标题音乐的远程资源索引为 0，但音频对象非空、名称为 `bgm_rtd_01`。原 `SoundManager.LoadBGM` 遇到索引 0 直接返回，`LoadAllBGM` 跳过已有对象，因此该槽位持有 APK 内置音频。重载逻辑误将它解析为远程导出 `bgm_rtd_00`，因不存在而触发事务回滚。

修复保留索引 0 的 APK 内置 BGM，只对实际远程 BGM 执行重新加载；远程 SE 沿用原 `GetSeResource(i+1)` 映射。保留音频槽位与导出名诊断日志，不记录服务端地址。修复后真机成功提交 78 资源快照，音频与两个依赖预制体共同激活；本次校验约 434 ms，资源此前已完整下载，因此没有重复下载。

## 独立代码审查

一次独立整体验查发现日志建立后、active 目录迁移前发生 I/O 失败时，显式回滚可能误删已接受目录。新增三种磁盘边界状态回归（日志后、两次目录重命名之间、接受标记重命名后），先复现错误再修复；通过 staged 是否已迁移来区分是否需要强制回滚。核心检查增至 46 项，包含 14 项存储检查；审查者复核该修复方案，并完成协议、补丁、构建与服务端路由检查，无其他已确认的重要缺陷。真机行为仍以实际验收为准。

故障回退的版本选择以完整历史闭包为单位：关卡接受的 8 资源快照不能满足启动所需的 76 个根，因此本次损坏发布失败后使用此前满足启动需求的完整 v1 快照，而不是从 v1/v2 历史中拼接资源。服务端恢复有效 v2 后，已实测重新校验并使用本地已下载内容，无需重下。

最新完整 APK 已安装；包含最新目录回滚修复、全部 180 个内置缓存文件。无变化启动约 353 ms 为单次实测，不宣称网络往返 p95。完整关卡结算、各提交点真实杀进程、真实磁盘满与峰值内存尚未覆盖；目录崩溃状态、取消、校验失败和事务恢复由核心回归覆盖。原项目已有的结算释放 native 闪退记录不属于本次已解决问题。
