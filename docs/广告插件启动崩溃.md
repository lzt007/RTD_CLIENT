# 旧广告插件启动崩溃与 Unity 入口绕过

2026-10-28 从 RTD_FAKE 迁移整理。本文记录历史 API28 模拟器上的 Java 入口异常，以及本项目当前的处理边界。旧广告插件入口问题与 [JNI 原生调用路径异常](JNI桥接与崩溃排查.md) 是两类独立故障。

## 故障与对照证据

历史正常 launcher 启动复现以下调用链：

```text
CARewardPluginActivity
  → CARAckCommon.getAUidByPackage
  → SharedPreferences
  → java.lang.SecurityException: MODE_WORLD_READABLE no longer supported
```

当时 pull 的已安装 base.apk 与原 APK SHA-256 一致：`1e95f5a91c6d3ead09c7f5462ace6238deda87392621f07758c5dc7439d784ec`。因此该次异常发生于已核对身份的原包启动入口，不能解释为客户端拆分打包后才引入的问题。

直接启动 `com.prime31.UnityPlayerNativeActivity` 后，历史进程 PID 4647 存活，但 `level0 Position out of bounds` 仍出现。该对照支持绕开广告 Activity，不能据此宣布场景布局、Loading、存档 JNI 或其他原生问题同时解决。

后续旧项目默认 package 的 paused-spawn 实验也误入 `CARewardPluginActivity`，因同类 MODE_WORLD_READABLE 异常经 AndroidRuntime 以 SIG9 退出。它与 Unity 运行中的 SIG11 不同，不应合并为同一崩溃。该轮宿主/来宾时钟未经独立校准，不能仅靠绝对时间推导精确因果。

## 既有绕过方式

旧项目 `start-rtd-game.ps1` 通过 ADB 显式启动 Unity Activity，核心命令为：

```powershell
# adb 需已在 PATH；将 <设备序列号> 替换为 adb devices 中的目标。
adb -s <设备序列号> shell am start -n jp.co.acquire.RTD/com.prime31.UnityPlayerNativeActivity
```

命令要求目标设备上已安装所需客户端；它不会安装 APK、设置网络转发或启动服务。实际登录还取决于配置中服务地址可达及服务已就绪。旧脚本固定 `emulator-5554` 并依赖旧项目 `enter-env.ps1`，因此这里提供独立命令说明，没有把旧环境依赖迁入构建链。本次没有执行该命令。

这种处理是绕过失效广告启动入口，不是修复广告 SDK 本身，不提供广告加载、第三方评价或广告奖励功能。按包名默认启动的工具仍可能走回广告 Activity，应使用支持指定 Activity 的启动方式。

## 当前 RTD_CLIENT 的状态

[build.py](../scripts/build.py) 复制原 APK 的 Manifest 和 DEX；替换表只涉及兼容所需原生库、Unity 资源、程序集和新增翻译资源。当前没有修改默认 launcher，没有补丁化广告 Java SDK，也没有内置设备启动脚本。**构建并签名成功不代表从桌面图标启动已避开此异常。**

游戏内部的平台策略已由 [LocalPlatformPatch.cs](../src/TracePatcher/LocalPlatformPatch.cs) 保留：

- `MMShop.OnClickReview` 与 `MMShop.OnClickNoahOffer` 只显示 LOCAL MODE 不可用提示，并走原 mode303 关闭流程。
- `MMQuest.SetEnableInductionButton` 强制关闭外部商店推广入口。
- 不发评价或广告奖励，不改变货币；不将原本隐藏的第三方入口强制开启。

这些托管补丁在 local-api 构建中应用，并运行 `Verify` 检查提示/关闭路径及推广隐藏约束。它们作用于游戏内按钮，不能替代启动前的广告 Activity 绕过。跳过 `SocialManager.Awake` 的 Facebook/Twitter 初始化也属于独立的社交启动阻塞处理。

## 验证范围与后续复核

历史证据支持 API28 环境下上述异常和直接 Unity 入口对照；本项目的开发签名 APK 尚未因此获得新设备验收。复核时应分别记录默认 launcher 和显式 Unity Activity 的结果、实际异常类型及 PID，不能把直接进入 Unity 当作完整登录成功。若要让桌面图标直接可用，需要另行修改并审计 launcher 配置或广告入口代码，再做安装与冷启动验收；本次仅迁移文档。

本项目静态构建范围见 [验证记录](验证记录.md)，配置与打包方法见 [开发部署](开发部署.md)。旧项目的 root 临时换包、签名失效诊断包及恢复命令属于历史实验流程，不能直接当成本项目开发签名 APK 的部署步骤。
