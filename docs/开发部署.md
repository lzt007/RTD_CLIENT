# 部署、移植与维护

## 配置和连接

根 `rtd.config.json` 是项目运行配置入口。`network.deviceHost` 是设备能访问的服务主机；不是监听地址。默认 127.0.0.1、资源端口 18765、游戏 API 端口 18766。真机/远端模拟器通常需改为宿主机 LAN 地址；本项目不会自动设置 adb reverse，也不会更改旧服务。API、公告与 common-text 路径也集中在此。构建完成后地址已写进派生程序集，修改配置需重建。

`paths` 指定原APK、缓存、翻译、字体、build、dist、keystore。`tools` 指定 Python、dotnet 可执行文件、JDK 根、Android SDK 根和 Cecil DLL。空 Python 由 PowerShell PATH 查找；SDK/JDK 空值从系统环境发现，JDK还支持从PATH中java.exe解析到其bin父目录（同时检查keytool.exe）。Python 构建入口自身只用标准库；可选字体生成器才需 `python -m pip install -r requirements.txt`。没有隐含的原项目目录依赖。

工具准备：复制 `tools/dotnet`、`tools/cecil/Mono.Cecil.dll`，或安装 .NET 10 SDK 并调整路径。Cecil 版本 0.11.6，可从 NuGet 包 lib/netstandard2.0 取得并放到配置路径。JDK 需 java/keytool；Android SDK build-tools 需 zipalign.exe 与 lib/apksigner.jar。`tools.cecil` 由构建时用于补丁器引用；tools 与原游戏数据均不随 Git 下载。

## 可重建补丁链

1. 验证原 APK 身份，从其 Managed 目录提取本轮引用，避免旧解包文件污染。
2. 从原始 level0 结构检查并生成既有 GameManager 84 字节布局兼容补丁。
3. 保持 ELF 节表/程序表，沿用已验收 getSource 原生修复算法：两个 ARM site `0x2e4048/0x2e4178`，将来源 `0x5002` 规范为 `0x1002`，32KiB 文件插入保留原始section。
4. 用原客户端裁剪版 mscorlib/UnityEngine 编译 RTDFlow、RTDRestoreCache、RTDLocalization；RTDFlow 保留观察功能，不代替游戏逻辑。
5. TracePatcher 保留 SharedPreferences/AndroidUtil JNI 桥接、gzip 桥接、关闭失效社交初始化、资源诊断、本地平台/战斗恢复兼容与 API 地址补丁。
6. RestoreCachePatcher 插入四处恢复缓存钩子并比较所有方法体/布局，StartupNoticePatcher 验证两处方法体与三处字符串公告站点。新维护链检查结构和作用范围，不要求曾经生成的候选 SHA。
7. 显示翻译钩子与配置地址注入，再运行解析器/加载器/IL 合约测试。
8. 重打包时保留原 DEX，去旧签名；zipalign -> 开发签名 -> zipalign check -> apksigner verify，并验证 native sites、原 DEX 与 ZIP 唯一成员。

原始 APK 哈希与 libunity 哈希仍锁定，因为二进制偏移/旧程序集结构只对该原版做过审计。支持另一原APK需重新审计，不要绕过检查。原生算法源自旧项目的 `build_input_compatibility.py.patch_native`，没有依赖旧候选 APK。

JNI 桥接的历史调用跟踪、显式加载库失败实验、null/文件语义与根因限制见 [JNI 桥接与崩溃排查](JNI桥接与崩溃排查.md)。旧广告 launcher 的 MODE_WORLD_READABLE 异常及显式 Unity Activity 启动命令见 [广告插件启动崩溃](广告插件启动崩溃.md)：当前构建保留原 Manifest/DEX，游戏内广告按钮兼容不代表桌面图标入口已经修复。

## 验证与发布界限

构建自动执行 `LoaderTests`（真实插件源码 + Unity test doubles）和 `LocalizationTests`（JSON + Cecil 读取实际DLL）。测试确保业务 GameText.Get/GetText、UILabel.text getter 原文不变，显示钩子位于 Replace/layout 前，输入保护钩子在 UIInput 初始化返回前，格式模板只在确认的 GameText→String.Format 显示调用点改写。日志见 `build/latest-build.log`（可用 PowerShell重定向生成），报告见 dist。

开发签名会改变安装签名，不能覆盖不同签名安装包。密钥存 build 并被忽略，需保持同一安装身份时自行备份。默认 android 密码仅本地开发使用，修改 signing 字段即可。构建不会安装，不声明运行时验收通过。

移植流程：复制整个文件夹（含 ignored inputs/resources/tools 与需要保留的 keystore），修正工具配置与设备网络，再构建。可删除 build 中间文件重新从原APK生成；若删除 keystore 则新建证书。服务端资源修复/敌人placeholder属于服务项目，客户端保留原缓存作原始输入，没有从客户端脚本改变任何服务器资源。

部署翻译映射 `inputs/localization/translation.json` 被Git忽略，正式词条由RTD_TRANSLATION项目统一维护。首次构建若文件缺失，自动从 `examples/translation.example.json` 初始化空对象；之后把翻译项目导出文件复制到该路径即可。
