# 年龄选择后商城卡在连接中

生产请求及HTTP访问记录均没有购买begin或point请求。原MMShopQuartz.Update在年龄选择／商品主数据检查之后进入商品等待阶段：原IL_0169调用StoreManager.get_isProductLoadFinish，false则返回并保留连接框。

上版本地支付补丁把Start替换为Initialize，只设置SDK初始化成功；get_isProductLoadFinish仍读取初始为false的mb_GetProductData。Products原先依赖其他入口调用，首次打开商店没有触发，形成等待环。此前桩测主动调用Products，遗漏了真实UI入口。

修复：把get_isProductLoadFinish重定向到ProductsReady，第一次查询时尝试从ClientData构造本地商品列表；主数据未到齐则保持false，随后查询可重试。只有实际有商品、列表构建完成才置加载标志。主商城与战斗内商城共用该getter。无需修改服务端，也不在客户端直接增加货币。

回归验证覆盖无主数据时等待、主数据到达后重试、未主动调用Products的首次商店进入，及既有订单重试／恢复／结算测试。模拟旧getter行为的临时副本在“主数据到达后重试”断言失败，修复版通过。构建契约检查新增该getter必须转入本地加载入口。仍需用户设备覆盖安装验收，不能用桩测代替真机结果。
