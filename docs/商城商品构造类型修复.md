# 商品列表仍卡住：反射构造参数类型

上一轮c40b53a只修复首次进入商城的加载门槛，遗漏实际数据类型不匹配，不能把上一轮桩测通过等同真机修复完成。

本轮直接检查原Assembly-CSharp.dll的MasterDataRTD.ShopProductMaster：id/name为String，price/point为UInt32；AndroidProduct构造函数却要求String、String、Int32、Int32、String。原CIL在求值栈上可以直接传递32位字段，但反射Activator.CreateInstance不能把装箱UInt32隐式窄化为Int32。

把桩数据point改成原DLL的UInt32后，原补丁稳定抛出MissingMethodException: Constructor on type AndroidProduct not found。该异常发生在商品列表构建期间，因而连接框仍在、购买begin不会发往服务端。原桩错误使用Int32，把异常隐藏了。

修复在共享CreateProduct工厂中显式Convert.ToInt32(point)，其他模拟购买及余额结算流程不变。回归不再只依赖自建桩：LocalStoreTests可接收原DLL路径，直接创建原ShopProductMaster，调用真实AndroidProduct构造函数；完整构建链强制传入原DLL执行该测试。原DLL的这些纯数据对象没有调用Unity原生引擎。该契约测试及既有本地购买测试在.NET和Mono下均通过，避免再次因桩字段类型失真而漏测。真机UI仍须覆盖安装后验证。
